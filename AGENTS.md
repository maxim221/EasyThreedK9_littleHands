# Little Hands Project Rules

These rules are mandatory for future Codex / agent work in this repository.

## Regression Checks

Before committing any change that touches printer motion, SD print workflow, Cura settings, firmware assumptions, G-code validation, or post-print recovery, run:

```bash
python3 -m py_compile tools/k9_control_center.py tools/k9_marlin_sd.py tools/k9_cura_slice.py
python3 tools/regression_checks.py
```

If a physical printer test is needed, ask the operator before moving axes or starting a print.

For changes to the GUI layout, language switching, busy controls, or in-app manuals, also run `xvfb-run -a python3 tools/ui_regression_checks.py`. These checks must remain isolated from printer serial access and persistent operator state.

## Do Not Regress Fixed K9 Behavior

- Do not use `G28` for this K9 workflow. The printer has no reliable endstop-based home in the current baseline.
- Do not leave service/manual/recovery moves at `M204 T1000`. The safe Little Hands service state is `M204 T80`; print G-code may set its own conservative print accelerations.
- Bed/logical `Y` service motion is the limiting axis. Keep long bed service/recovery moves at `F240`; keep manual bed jog at the validated working UI/manual context `F600` with `M204 P80 T80`, honoring the selected UI step as one move.
- Manual bed jog must match the validated direct-control sequence and must not open a separate pre-move `M114` query/session before the jog. This K9 has no endstops, so raw negative coordinates are not a physical-edge guard in this workflow.
- During operator-requested bed jog diagnostics, the operator watches the physical bed and keeps it away from hard stops. Do not assume "bed is at the edge" or diagnose a buzz/no-move symptom as a physical hard-stop unless the operator reports that it is actually at the edge; still keep app-level safety and recovery guards.
- Head left/right service/recovery motion should stay around `F900`; manual head left/right jog uses the smoother one-move diagnostic context `F600` with `M204 P80 T80`, no separate pre-move `M114`. Because power-cycle / skipped manual X moves can leave Marlin at stale negative X while the physical head did not move, manual X jog may first declare a local neutral coordinate (`G92 X50`) and then move only the selected step within that local window.
- A successful `ok`/`M400` after manual X jog is not proof that the X carriage physically moved on this K9. Same-session post-jog `M114` is allowed for diagnostics, but it is still only Marlin's logical position. If the operator reports no physical X movement, keep home uncertain, do not trust saved-start recovery, and require a visual/manual start reset before printing.
- A successful saved-start return with `ok`/`M400`/`M114 X0 Y0 Z0` is likewise not physical proof on this K9. After any X/Y return, keep home uncertain until the operator visually confirms the head is near-left, the bed is fully back, and the nozzle is at the saved height. A negative confirmation must keep SD start blocked and require short watched jogs/manual start restoration followed by `Save start`.
- If a post-print X return only buzzes while watched manual moves work, treat it as an application motion-profile failure, not mechanical sticking. Known-pose recovery must use the exact manual-X coordinate context for every acknowledged segment: re-declare local neutral `G92 X50`, make one move no longer than `50 mm` at `F600` with `M204 P80 T80`, then `M400`. Do not substitute absolute targets derived from the saved/predicted X coordinate. Keep home uncertain if physical return did not complete and require visual confirmation before saving start again.
- All manual jog, bed-level, SD start-from-home, saved-start return, recovery, and presentation service moves must use the ok-waiting serial helper plus `M400`/soft `M204 T80` where appropriate. Do not go back to fire-and-read command batches for axes.
- Bed-level point buttons must stay disabled unless `Save start` has made the current home trusted, and the bed-level handler must also refuse movement without trusted home.
- Post-print saved-start return must not re-declare coordinates from saved `M114` while the live Marlin session still has a trusted saved zero.
- Never run automatic post-print axis movement for a print state restored from logs / app restart. Startup, reconnect, telemetry recovery, and restored completion detection may update UI/logs only; physical completion moves are allowed only for a trusted current live session.
- Stopped-print recovery must preserve interrupted X/Y from the pre-`M524` print position, but account for the K9 head lift after stop by using the raised post-stop Z when available. Do not treat the reset-like post-stop `X0 Y0 Z5` as real X/Y home.
- Do not automatically return X/Y from a stopped-print pose. Field validation on 2026-10-10 showed that this firmware's `M524` / `EVENT_GCODE_SD_ABORT G28XY` physically displaced the bed by an unmeasured amount after the pre-stop pose was captured; replaying that pose left Y about 20 mm short even though `M114` ended at zero. Retain the pose for diagnostics only. After Stop, require short operator-watched manual jogs followed by `Save start`; neither GUI nor agent API may claim an automatic physical return.
- Normal `Stop` is not the emergency stop path. It should capture `M114` as early as possible before `M524`, pause, retry `M114` without a pre-capture `M400`, try a controlled safe Z lift, then stop SD/heaters and keep that stopped-print recovery pose. Manual jogs after Stop must update this recovery pose instead of deleting it.
- Before the normal Stop path sends `M25`, performs its stop lift, or sends `M524`, query `M27` in the same serial session. If a complete acknowledged reply already says `Not SD printing`, the file has ended: preserve the captured final pose, skip `M25` / the stop lift / `M524`, and only shut down heaters and the fan. On this firmware `M524` injects `EVENT_GCODE_SD_ABORT G28XY`, which can physically displace X/Y while resetting the reported logical coordinates; never invoke it after a proven completed print.
- If the nozzle is known to be at saved start (`Z0`) before SD start, lift to safe Z clearance before enabling either the hotbed or hotend, then explicitly return to saved start before `M24`. This prevents bed heat at the nearby nozzle from triggering the shared fan and slowing hotbed warmup.
- Do not rewrite early startup `M109` to `M104` for new K9 G-code. The stable SD workflow is: require the printer to already be at the saved start, prove heat with staged host-side `M104` targets around `60/100/150/200C`, run one final blocking `M109` preheat gate with passive temperature parsing, return to the saved start, then send `M23`/`M24`. The file-local `M109` remains as a second safety wait, but Little Hands must not rely on it as the only heat gate; that regressed into cold movement after post-print restarts. Never go back to the old `M104` plus repeated `M105` polling loop. On host-preheat abort, send `M108` before `M104 S0`.
- UI SD-start paths must block unless the app knows the printer is physically at the saved start. Once host preheat has completed and any preheat lift has been undone, use the no-service-move SD start path (`M23`/`M24`) so the file's initial `G92 X0 Y0 Z0` is executed at the real saved start, not after an extra Little Hands axis dance.
- All UI SD-start paths must use the shared lift-then-bed-then-hotend preheat wrapper. If either heater or the preheat clearance return fails before `M24`, attempt `M108`, `M104 S0`, and `M140 S0`, and preserve any failed-lift recovery marker. Mark home uncertain and require the next-start power cycle only when firmware halted/reset, heater shutdown is unconfirmed, or the known clearance return remains unacknowledged; a cleanly cancelled/failed preheat with confirmed heater-off and confirmed lift return does not require a power cycle. A successfully warmed bed must not remain on after a failed hotend preheat.
- G-code validation must check every positive hotend/bed target, not only the first/last one. Reject all forms of bed `M190` (including `R`, `S0`, or no target), mismatched bed targets, and invalid/conflicting hotbed markers. Parse the latest complete temperature report without mixing samples or treating bed `B@` as hotend `@`.
- While a user USB operation is pending, keep port selection/find/disconnect disabled and refuse app closure so a worker cannot lose its port or abandon heating/upload cleanup. Preserve these guards when a window is rebuilt or its language changes.
- If a G-code upload is cancelled, fails verification, or leaves a partial SD file that Little Hands cannot delete, the matching SD name and likely aliases must stay blocked for SD start until the file is deleted or overwritten by a clean upload. Do not let a partial/unknown-profile file start just because it appears in the SD list.
- Do not require a printer power cycle after an ordinary completed print or an acknowledged normal Stop. Set the next-start power-cycle gate only when there is evidence that it is actually needed: firmware reset/thermal halt, hard stop, unacknowledged Stop/start, unconfirmed heater shutdown/USB-controller state, or an unacknowledged known-lift return. Position/home recovery and bed-clear confirmation remain required independently.
- When that exceptional gate is active, Save start may collect the explicit power-cycle confirmation in a separate default-No prompt. Clear the gate only after the zero declaration succeeds and the operator explicitly answered that the 5–10 second cycle was already completed; answering No may save the pose but must retain the gate.
- If hotend preheat fails after Little Hands lifted Z for clearance, first undo that known lift with a relative move of the same distance (`G91` / `G1 Z-<clearance>`), then surface the error. Do not recover with `G1 Z0` because a USB/controller reset can make the raised pose become the new logical zero. If the relative return fails or USB disappeared, mark home uncertain and require the operator to visually confirm the physical start and press `Save start` again.
- If that failed-preheat relative return is not acknowledged, preserve a dedicated failed-preheat-lift recovery marker. `Stop` must not discard it. The saved-start return button may offer only a guarded relative Z-down retry after the operator confirms that print did not start and axes were not moved by hand. After that relative Z-down succeeds, immediately re-declare the recovered physical start with `G92 X0 Y0 Z0`; after a power cycle Marlin's logical Z can be stale. A manual jog may clear this marker only after the move is acknowledged; a failed jog must keep the marker. Motor-off, hard stop, or a newly saved start must clear this marker.
- If Marlin reports `Heating failed, system stopped! Heater_ID: E0` during preheat after a clearance lift, treat it as firmware thermal halt: preserve the preheat-lift recovery marker, do not keep sending axis recovery commands until after power cycle, and tell the operator that the heater output was commanded but the hotend temperature did not rise.
- If Marlin reports a hotend target and positive heater output during preheat, do not abort only because the first `75s` rise is small. This K9 hotend/sensor can show a slow-start and then climb rapidly. Log the slow rise and keep waiting up to the full preheat timeout. Still abort quickly if the target is lost (`/0C`) or heater output stays `@0`.
- Faint clicking during the early hotend slow-start phase is a documented field observation on the current working setup. Do not tune firmware, fan logic, preheat stages, or Cura temperature only to remove those faint clicks if staged preheat later climbs normally and printing remains stable. Escalate only for loud clicking, smell, hot connectors, target loss, heater output stuck at `@0`, or failure to reach the staged temperature gates.
- Manual filament feed/retract is a diagnostic/manual-load path, not part of SD printing. It must be blocked while an SD print is active, must not enable cold extrusion (`M302`), must require a confirmed hotend temperature of at least `180C`, and must use relative E (`M83`), a slow E feed, `M400`, and restore `M82` through the ok-waiting helper.
- If Stop succeeds during the post-`M24` quiet window but `M114` is not captured, the saved-start return path may only offer guarded live-session return while warning the operator to clear the bed and visually confirm/save start afterwards. Clear that marker on new print starts, hard stop, motor off, port changes/disconnects, or after the attempt.
- If USB drops during a real SD print and the app later still has a stale active-print marker, saved-start recovery must not blindly block when a matching valid `LH_END_GCODE_V1` predicted print-end exists and there is no recent SD progress. It may offer the guarded predicted-end recovery prompt after the operator confirms the print is finished, the bed is clear, and axes were not moved.
- If USB drops during SD printing, keep the `LH_END_GCODE_V1` predicted final pose in application state. When a restored print reports `Not SD printing`, surface the explicit finish-confirmation recovery window when that pose is valid; do not treat the reply itself as proof of completion. The operator must explicitly confirm normal print completion and model removal; only after that may post-print return use the saved predicted final pose for guarded recovery.
- If USB re-enumerates the CH340 printer to a new `/dev/ttyUSB*` name after a disconnect, guarded saved-start recovery may automatically switch to the single currently visible safe printer-like port. Do not require manual `Find` when exactly one CH340/ACM printer port is present.
- Post-print return must use the same guarded recovery path as the manual-control saved-zero button (`Go to saved start` / `К сохранённому старту`). Do not re-add a separate SD-panel `After print: return` / `После печати: к старту` button or any fire-and-forget terminal-style movement path in the UI.
- Do not discard an active-print marker or a valid predicted print-end recovery pose merely because telemetry is stale or the application restarted. Preserve both until the operator explicitly confirms completion, stop, or failure; stale telemetry alone must not unlock service moves.
- Home is trusted only after `Save start` or a confirmed Little Hands recovery/return. Port changes, disconnects, motor-off, hard stop, failed jog/recovery/start, and stopped prints must mark home uncertain or invalid and block SD start until the operator re-saves or confirms recovery.
- End G-code should present the bed toward the operator with gentle motion: `M204 P250 T120`, `G1 X95 F900`, `G1 Y95 F240`.
- Do not add `M18` / `M84` at the end of print files; Little Hands needs steppers available for recovery.
- Do not let Cura control the single K9 fan as part cooling. Slicer `M106/M107` must be stripped or disabled.
- Do not directly slice raw `moduleBot.STL` without checking orientation. Use the validated oriented STL or explicitly inspect Cura Preview.
- Current firmware baseline is `LH v5 ... Watch180`. Do not reduce hotend `WATCH_TEMP_PERIOD` below `180s` unless a cold-start physical heat test proves the K9 no longer false-trips `Heating failed`.
- `LH v6 EXP ... Bed10K Max70` is the current experimental controlled-hotbed branch for the installed `~10k` NTC bed sensor on the board `-TB+` input. The AliExpress product listing for this EasyThreed K9-compatible bed advertises max hotbed temperature `70C`; with Marlin `BED_MAXTEMP 70` and `BED_OVERSHOOT 10`, the practical maximum bed target is about `60C`. Operator-watched `M140 S30` and `M140 S35` sanity tests on 2026-06-10 showed smooth `B:` rise and `B@:0` after `M140 S0`, but the public printing baseline remains `LH v5` with external warm mat / Cura bed temperature `0`.
- `LH v7 EXP ... Bed10K Max70 BedWatch180` is the controlled-hotbed candidate for cold airflow. It changes `WATCH_BED_TEMP_PERIOD` from `60s` to `180s` while keeping `WATCH_BED_TEMP_INCREASE 2`, bed thermal-runaway protection, `BED_MAXTEMP 70`, and the `60C` application target cap. Do not shorten the bed watch window or disable bed thermal protection to hide slow heating.
- `LH v8 EXP ... BedGuard3C60s` is the installed follow-up candidate. It retains the v7 `WATCH_BED_TEMP_PERIOD 180` / `WATCH_BED_TEMP_INCREASE 2` heating watch and changes only the active bed thermal-runaway guard from `2C/20s` to `3C/60s`. A watched center-airflow test still pulled the bed from about `59.5C` to `55.65C` at full `B@:127`; v8 stayed responsive, so do not widen this guard or claim that firmware can make the bed hold `60C` under airflow.
- `LH v9 EXP ... LH1` is the installed Little Hands protocol candidate. Its operator-approved non-motion validation confirmed `Cap:LITTLE_HANDS_PROTOCOL:1`, atomic `M930` snapshots, session-token retention, monotonic sequence values, idle SD state, zero heater targets/outputs, and the retained v8 motion configuration. Do not promote it to the printing baseline until the application uses the protocol and a separately approved watched print validates the complete path.
- `LH1` logical and step-counter coordinates are telemetry, not proof of physical K9 axis motion. A changed/zero session token after binding, a reset sequence, malformed snapshot, or impossible SD cursor must invalidate that snapshot; none may authorize unattended return-to-start. When capability `LITTLE_HANDS_PROTOCOL:1` is advertised, periodic active-print telemetry must use one atomic `M930` snapshot instead of preceding it with separate `M105`/`M27`/`M114` requests; keep the legacy polling fallback for firmware without the capability or a rejected snapshot.
- Persist the active print's LH1 host token and last accepted sequence/uptime/cursor atomically. After an application or computer restart, query plain `M930` first and compare it with that saved session; never send `M930 S...` to overwrite the firmware token while an active print marker is restored. A matching session must reattach the GUI to live telemetry and the explicit controls safe during a print (Pause, verified Resume, Stop, emergency heater shutdown), while jog/upload/restart/return stay blocked. Reattachment itself must not send a print or motion command. A mismatch keeps the print/result unknown and unsafe controls blocked.
- Agent/script control must go through the owner-only local Control Center API and its existing single-worker/safety guards; do not add a raw remote G-code endpoint or a second competing serial connection. Physical jogs and print starts still require explicit operator-watching confirmation. Treat an accepted asynchronous API command as pending until `status.operation` reports completion, and never treat `ok`, `M114`, or `LH1` coordinates as proof of physical motion.
- For further controlled-hotbed validation, first require cold `M105` to show plausible room-temperature `B:` and `B@:0`; use bounded operator-watched targets and always turn the bed off with `M140 S0`. During the first `M140 S30` test, the operator's surface sensor read a few degrees hotter than Marlin `B:`, so keep temperature targets conservative until calibration is better understood. Ordinary Cura bed temperature must stay `0`. The selected local policy is `60C` preheat followed by `55C` print maintenance: new files carry `;LH_EXPERIMENTAL_HOTBED_TARGET:60`, `;LH_EXPERIMENTAL_HOTBED_PRINT_TARGET:55`, and non-blocking `M140 S55`. Little Hands must host-preheat and verify the bed at `60C`, complete staged hotend preheat, then command and verify the reported `55C` setpoint immediately before `M24`; any failed handoff must run the normal heater-off cleanup and prevent SD start. Legacy one-marker files retain their single target. App/manual and slicer targets must stay at or below `60C`, preserving `Bed10K Max70` firmware and its thermal protections. Manual presets are `35/40/50/55/60C`; host bed preheat may wait up to `900s`. Existing G-code keeps its original policy until re-sliced and cleanly uploaded. Do not add `M190` to K9 SD files.
- For bed leveling after the installed hotbed, remember the current Cura start declares the physical start as `G92 X0 Y0 Z0` and the first layer already moves to about `Z0.20`. Use a `0.05 mm` feeler gauge with light drag at all five Little Hands leveling points (`FL/C/FR/BL/BR`) while the app is at `Z0`; treat `0.10 mm` as an upper sanity check, not the target gap, unless a new first-layer validation proves otherwise.
- SD-start hotend preheat must stay staged: prove heat with `M104` stages around `60/100/150/200C`, then use final blocking `M109` as the last gate before `M24`. Do not go back to a single cold `M109 S226` start without a new physical validation.
- Keep the current cautious Cura baseline for this small K9 mechanics unless a new physical test proves a faster profile is safe: print/infill `11 mm/s`, wall/top-bottom `8 mm/s`, travel `25 mm/s`, first layer `6 mm/s`, skirt/brim `21 mm/s`, bridge `7 mm/s`. Do not drop first-layer/brim to `4 mm/s` without an explicit physical test; it made the print crawl rather than simply reducing speed by 30%.
- The 2026-10-09 backpack result showed that the 45° / 50% / 0.32 mm / 0.4 mm easy-release trial still produced effectively solid supports. The 2026-10-10 `55°` / `5%` / no-interface / `0.64 mm` Z / `0.8 mm` XY backpack trial removed the unwanted support column and did break away, but still required excessive force; its final small layers also delaminated. The explicit follow-up `max-easy-release` one-off preset therefore uses `60°`, `3%`, no interface/roof, `0.80 mm` top/Z gap, and `1.2 mm` XY gap. For this one-off backpack profile only, use `225C` after the `226C` first layer, `102%` general flow, `103%` wall/skin flow, and `10s` minimum layer time to improve bonding of the small upper layers. This deliberately accepts a much rougher supported underside and must not become the default for other models until physically validated. The normal validated profile remains `50°`, `8%`, `30%` interface/roof at `0.32 mm`, `0.48 mm` top/Z gap, `0.5 mm` XY gap, `220C`, `101%` general/wall/skin flow, and `15s` minimum layer time. Both retain `100%` infill flow and `sharpest_corner` seam placement.
- Keep Cura `Preferences -> General -> Add machine prefix to job name` disabled (`[cura] jobname_prefix = False`). The K9 workflow should save `model.gcode`, not `CFFFP_model.gcode`.
- Keep Cura's active machine on the warm-mat container (`[cura] active_machine = lilHands_k9_warmmat`). If Cura falls back to the older `lilHands` machine, it can save G-code with the old `G1 Z10.0 F1800` start and no `;LH_EXPERIMENTAL_HOTBED_TARGET:60`, so the controlled hotbed will not heat even though the file was just saved from Cura.

## Recovery Evidence And Retained Pauses

- During host preheat, keep Stop available as a cancellation request to the existing serial worker. Closing the window requests the same cancellation and may complete only after the worker exits and fresh heater targets/outputs confirm shutdown. Keep manual axes, port changes, and competing USB tasks locked until cleanup finishes. Cancellation must prevent M24, interrupt M109 with M108, and undo only the known current clearance lift; preserve the lift marker if return fails.
- Retain one serial connection throughout bed preheat. On preheat failure, allow bounded reconnect attempts for heater-off commands only; match the printer's VID/PID and serial number or USB location before selecting a re-enumerated port. Never resume heating or move axes automatically after that reconnect.
- If a failed-preheat-lift marker is present, Save start must ask a default-No confirmation that the operator physically restored the nozzle near the bed. Do not silently erase that marker because the operator clicked Save start at a raised pose. Declare the saved zero through the acknowledged helper.
- A trailing `ok` does not make an `echo:Unknown command`, damaged serial reply, or firmware error successful. Reject these replies before any following service movement; accept only an actual `ok` response line (or a complete M114 position for the existing position-query exception). After a reconnect, heater-off targets and outputs require a fresh complete temperature report; do not infer shutdown from a bare or mismatched acknowledgement.
- SD telemetry records are diagnostic observations, not exact executable restart checkpoints. Preserve raw G-code XYZ (before UI Y/Z remapping), individual reply timestamps, SD byte/total, source G-code hash/copy, and firmware identity. Write state atomically. Never construct or execute an automatic G92/M26/G-code-tail recovery from stale observations or predicted print-end for an unfinished part.
- Resume must use an acknowledged M25 pause followed by M400 and captured file/SD cursor/position/temperature. Recheck these through a single serial session before M24; refuse changed/cold/missing state and suspect files. After reconnect/restart, require explicit operator confirmation that printer power, axes, and part were untouched. Consume the pause record durably before sending M24 so a missing acknowledgement cannot cause a repeated start. No M21/M23/G92 during resume checks.
- A missing Stop acknowledgement is not a successful stop: attempt all heater-off commands, report unknown heat/position, and block automatic return. Never restore a live-session-only return flag across an app restart. Poll using one serial connection per cycle, keep active-print position sampling rate-limited, back off strongly on missing replies, and never refresh the age of an SD sample from a locally generated status string. Metrics/status inspection must not mount or reselect SD during a print. Treat a changed Linux USB enumeration generation as a physical detach/attach event, not as an ordinary late Marlin reply.
- After `M24` has been acknowledged/sent, missing or stale `M105`/`M27` telemetry must never send `M524`, clear the active-print marker, or unlock service/return moves. Keep the print persisted as active with unknown telemetry across timeouts and app restarts. Only an explicit operator Stop, positively confirmed normal completion, or an explicit operator result decision may end that active state.
- When the operator explicitly saves a physically restored start after an unknown/abandoned restored print, durably close that old result before allowing another start. A later app restart must not resurrect the older `PRINT_START` from the runtime log over a newer terminal persistent state.

## Documentation

Keep manually saved Cura G-code in the project `gcode/` directory instead of the repository root. Local Cura 5.11 uses `[local_file] dialog_save_path` in `~/.config/cura/5.11/cura.cfg` to suggest this directory; edit preferences only while Cura is closed. Existing `exports/` helper output and `card_backups/` archives retain their separate purposes.

When a workflow or safety rule changes, update:

- `PROJECT_LOG.md`
- relevant files under `docs/`
- this file, if the rule affects future agent behavior

The in-app manuals load from `docs/USER_GUIDE.md`, `docs/USER_GUIDE.ru.md`, and `docs/USER_GUIDE.zh.md`. Update all three together; keep operator actions concise and retain the explicit recovery conditions. Check important controls remain visible at `1080x680` and `1280x780` in all three languages.
